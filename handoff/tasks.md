## 1. 개요
설정은 설정 화면에서 사용자가 데이터 출처마다의 API 키를 넣어 확인하고 저장하며, 저장된 키를 보고 지우는 기능이다. 이번에는 설정 화면을 Hak이 확인한 시안과 같은 모양으로 다시 그리고, 위쪽 줄에 뒤로 가기 버튼을 더한다. 지금 화면은 Material의 기본 부품으로 짜여 있어 시안과 모양이 다르고, 시장 분위기 화면에서 들어온 뒤 돌아가는 버튼이 없다.
화면을 다시 그리면서 설정 안에 따로 있던 딱지, 출처 문구, 키 보기 아이콘을 공용 화면 요소(`core/ui`)의 것으로 바꾼다. 두 화면의 딱지와 출처 문구가 같은 글과 색으로 보이게 하기 위함이다.
키를 확인하고 저장하고 내주는 동작은 바꾸지 않는다. `feature/settings/domain`, `feature/settings/data`, `feature/settings/di`와 `core/network`는 고치지 않는다. 화면의 문구와 동작(무엇을 누르면 무엇이 되는지)도 뒤로 가기와 가려진 키의 모양 말고는 그대로다. 앱의 첫 화면은 이미 시장 분위기라 그것을 위해 고칠 것은 없다(R-01은 없어진 요구사항이다).

**지시**
- 설정 안에 따로 있던 딱지 열거형 `KeyBadge`를 지우고, `SourceCardUiState.badge`의 종류를 `core/ui`의 `KeyBadgeKind`로 바꾼다. 값의 뜻은 그대로다: `NONE`(키 없음) / `SAVED`(저장됨) / `INVALID`(틀림). 어느 때 어느 딱지를 고르는지는 바꾸지 않는다. (P-13, R-05)
- 화면 상태의 나머지 모양은 그대로 둔다. 단위 3의 화면과 테스트가 이 모양에 맞춘다.
  - `SourceCardUiState(source, nameRes, descriptionRes, badge: KeyBadgeKind, issueUrl, mode)`
  - `CardMode.Input(text, inputEnabled, saveEnabled, checking, errorBorder, messageRes)`
  - `CardMode.Saved(displayKey, revealed, showRejectedNotice)`
- 카드의 `nameRes`와 `descriptionRes`는 `core/ui`의 `SourceLabels.nameRes(source)`, `SourceLabels.descriptionRes(source)`에서 얻는다. SourceCardInfo에서는 이름과 설명을 지우고 키 발급 페이지 주소(`issueUrl`)만 남긴다. 주소는 그대로다: Twelve Data `https://twelvedata.com/register`, FRED `https://fredaccount.stlouisfed.org/apikeys`. (P-13, R-03, R-04)
- 가려진 키는 키의 길이와 상관없이 점(`•`) 12개, 빈칸 하나, 키의 끝 네 글자로 만든다. 키가 네 글자 이하면 점 12개만으로 만들고 빈칸과 글자를 붙이지 않는다. `SettingsViewModel.mask(key: String): String`이 이 일을 한다. 키 보기가 켜져 있으면 지금처럼 `displayKey`가 키 전체다. (P-14, R-07, R-13)
  - 이유: 키의 길이만큼 점을 찍으면 32글자 키가 칸을 넘친다.
- SettingsScreen은 이 단위에서 컴파일되게만 맞춘다: 딱지를 그리는 곳을 `KeyStatusBadge(card.badge)`로 바꾸고, 화면 안의 딱지 그리기(BadgeChip)를 지우고, 미리보기의 `KeyBadge`를 `KeyBadgeKind`로 바꾼다. 화면을 시안대로 다시 그리는 것은 단위 3에서 한다. (P-13)

| 설정 · 키 보기와 확인하지 못한 키 | `project/Settings-Reveal.dc.html` | 위 카드: 저장 모드에서 키 보기를 켬(revealed가 참). 아래 카드: 입력 모드에서 거절이 아닌 이유로 저장하지 못함(errorBorder는 거짓, 칸 아래 안내) |

- 시안과 다르게 만드는 곳. 채팅이 미리 찾은 차이다. (R-45)
  - "키 없음" 딱지의 바탕은 시안의 #ECEEF1이 아니라 테마의 값이다. 딱지는 KeyStatusBadge를 그대로 써서 시장 분위기 화면과 같게 한다. (P-13)
  - "설정 · 키를 넣기 전"과 "설정 · 저장됨과 틀림"의 "키 발급받기"가 가리키는 주소는 자리만 채운 것이다. 카드의 issueUrl이 맞다. (R-15)
  - 뒤로 가기 버튼을 읽어 주는 글은 시안의 "뒤로"가 아니라 "뒤로 가기"다.
  - 시안의 글꼴(Noto Sans KR)은 쓰지 않는다. 테마대로 기기의 기본 글꼴을 쓴다.
  - "키 발급받기"는 밑줄 없이 강조 색으로 적는다. 시안은 브라우저가 링크에 밑줄을 그을 수 있으나, 시장 분위기 화면의 "FRED API 이용 약관" 링크와 같은 모양으로 맞춘다.
  - 칸 아래 안내의 알림 아이콘은 글이 한 줄이든 두 줄이든 첫 줄에 맞춘다(위쪽 맞춤, 아이콘 위 여백 1, 글의 줄 높이 1.5배). 한 줄짜리를 그린 시안 둘은 가운데 맞춤으로 그려져 있으나, 한 줄일 때의 결과는 같다.
  - 시안의 진행 표시는 멈춘 그림이다. 앱에서는 시장 분위기 화면의 진행 표시와 같은 방식으로 돌리고, 크기와 굵기와 색만 단위 1의 "확인 중 고리" 값으로 한다.
  - 시안은 높이가 고정된 그림이다. 앱에서는 아래의 밀어 보기를 따른다.
  - 시안에 없는 것: 지우기를 묻는 창은 지금처럼 Material의 기본 창(AlertDialog) 모양 그대로 둔다. 입력 칸에 초점이 있을 때는 테두리를 바꾸지 않고(시안의 테두리 그대로) 커서만 강조 색으로 보인다. 빈 입력 칸의 "키를 붙여 넣으세요"는 테마의 비활성 색으로 적는다(시안은 브라우저의 기본 회색이다). (P-12)
- 화면은 Material의 기본 모양을 가진 부품(TopAppBar, Card, OutlinedTextField, Button, OutlinedButton, IconButton)으로 짜지 않고 테마의 값으로 직접 짠다. 기본 부품은 높이, 여백, 모서리, 색이 정해져 있어 시안의 값과 맞지 않는다. 입력 칸은 기본 입력 부품(BasicTextField)에 테두리와 바탕을 그린다. 시장 분위기 화면(MarketMoodScreen)이 같은 방식으로 만들어져 있다. 그 화면 안의 부품은 그 파일에서만 쓰게 되어 있으므로 가져다 쓰지 않고, 설정 화면에 필요한 것은 설정 화면에 둔다. (P-12)
- `SettingsScreen(onBack: () -> Unit, viewModel: SettingsViewModel = hiltViewModel())`. 받은 상태를 그리고 입력을 넘기기만 한다. 판정과 형식 바꾸기(키 가리기 포함)를 여기에 두지 않는다.
- 화면은 위에서 아래로 위쪽 줄, 안내, 출처 카드 순서다. 카드는 uiState.cards의 순서대로 하나씩 그린다. 내용이 화면보다 길면 위쪽 줄은 제자리에 두고 그 아래를 위아래로 밀어 본다. 상태 표시줄과 아래쪽 시스템 영역에 내용이 가리지 않게 하고(시장 분위기 화면과 같은 방식), 키보드가 올라와도 입력 칸과 저장 버튼까지 밀어 볼 수 있게 한다. (R-02, R-03, R-10)
- 위쪽 줄: 왼쪽부터 뒤로 가기 버튼(`AppIcons.Back`), 화면 이름 "설정". 뒤로 가기 버튼을 누르면 onBack을 부른다. 돌아가는 일은 화면이 하지 않는다. 기기의 뒤로 가기를 화면에서 가로채는 코드(BackHandler 등)는 두지 않는다. (R-02, R-44, P-11)
- 안내: "데이터를 받으려면 출처마다 키가 필요합니다. 키는 이 기기에만 저장됩니다." (R-02)
- 카드의 머리: 왼쪽에 출처 이름과 그 아래 무엇에 쓰는 키인지 한 줄, 오른쪽에 `KeyStatusBadge(card.badge)`. 카드의 상태와 상관없이 늘 있다. (R-04, R-05, P-13)
- 입력 모드(`CardMode.Input`)의 카드는 머리 아래에 위에서 아래로 아래와 같다. (R-06)
  - 이름표 "API 키", 그 아래 입력 칸. 한 줄짜리이고, 치거나 붙여 넣을 수 있다. 비어 있으면 "키를 붙여 넣으세요"가 보인다. 글자가 바뀌면 onKeyInputChange에 넘긴다. (R-06, R-10)
  - inputEnabled가 거짓이면 입력 칸을 비활성 모양(비활성 입력 칸의 테두리와 바탕, 흐린 글)으로 그리고 고칠 수 없게 한다. (R-32)
  - errorBorder가 참이면 입력 칸의 테두리를 오류 테두리 색, 굵기 2로 그린다. (R-08)
  - messageRes가 있으면 입력 칸 아래에 알림 아이콘(`AppIcons.Alert`)과 그 글을 경고 글 색으로 보인다. 글이 길면 다음 줄로 넘긴다. 거절됐을 때(R-18), 연결이 안 됐을 때(R-19), 그 밖의 이유로 확인하지 못했을 때(R-30), 기기에 저장하지 못했을 때(R-43)가 모두 이 모양이고 글만 다르다. (R-08, R-18, R-19, R-30, R-43)
  - 그 아래 한 줄: 왼쪽에 "키 발급받기"와 그 아래 "무료, 카드 등록 없음", 오른쪽에 저장 버튼 자리. "키 발급받기"를 누르면 카드의 issueUrl을 브라우저로 연다. (R-06, R-15)
  - 저장 버튼 자리: checking이 참이면 돌아가는 진행 표시와 "확인 중"이 든 확인 중 표시를 보이고, 누를 수 없다. 아니면 "저장" 버튼을 보인다. saveEnabled가 참이면 강조 색 바탕의 누를 수 있는 버튼이고 누르면 onSaveClick, 거짓이면 비활성 모양(비활성 채운 버튼의 바탕, 비활성 색의 글)이고 눌러도 반응하지 않는다. (R-26, R-32, R-11)
- 저장 모드(`CardMode.Saved`)의 카드는 머리 아래에 위에서 아래로 아래와 같다. 입력 칸, 발급 안내, 저장 버튼은 없다. (R-07)
  - 이름표 "API 키", 그 아래 저장된 키 칸. 칸 안 왼쪽에 displayKey, 오른쪽에 키 보기 버튼. (R-07)
  - revealed가 거짓이면 displayKey(가려진 키)를 "가려진 키" 글자로 한 줄에 적고, 버튼은 `AppIcons.Eye`에 읽어 주는 글 "키 보기"다. revealed가 참이면 displayKey(키 전체)를 "키 전체" 글자로 적되 한 줄에 다 들어가지 않으면 글자 사이 어디서든 다음 줄로 넘겨 잘리지 않게 하고, 칸의 높이를 그만큼 늘린다. 이때 버튼은 `AppIcons.EyeOff`에 읽어 주는 글 "키 가리기"다. 버튼을 누르면 onRevealToggle. (R-07, R-13, R-33, P-14, P-15)
  - showRejectedNotice가 참이면 저장된 키 칸의 테두리를 오류 테두리 색, 굵기 2로 그리고, 칸 아래에 알림 아이콘과 "키가 거절됐습니다. 지우고 다시 넣어 주세요."를 입력 모드의 칸 아래 안내와 같은 모양으로 보인다. 키는 가려진 채로 둔다. (R-28)
  - 그 아래 오른쪽 끝에 "키 지우기" 버튼(테두리만 있는 버튼, 글은 경고 글 색). 누르면 "이 키를 지울까요?"라고 묻는 창이 뜬다. 확인을 누르면 창을 닫고 onDeleteConfirm, 취소를 누르면 창만 닫는다. 창을 띄울지는 지금처럼 화면 안의 상태로 둔다. (R-14, R-34, R-35)
- 화면이 보이지 않게 되면(수명 주기 ON_STOP. 화면 회전은 뺀다) 지금처럼 ViewModel의 onScreenHidden을 부른다. 이 동작은 바꾸지 않는다. (R-33)
- KeyVisibilityIcons를 지우고 키 보기 버튼은 `AppIcons.Eye`, `AppIcons.EyeOff`를 쓴다. 단위 2에서 남겨 둔 화면 안의 딱지 색 상수도 쓰지 않게 되므로 지운다. (P-15, P-13)
- `strings.xml`에 뒤로 가기 버튼을 읽어 주는 글을 더한다: `action_back` = "뒤로 가기". 그 밖의 문구는 있는 것을 그대로 쓴다. (R-02)
- Android Studio 미리보기(@Preview)를 화면 전체(위쪽 줄, 안내, 카드 둘)로 넷 둔다. 시안의 네 화면과 같은 상태다. 확인 중과 틀림(저장 모드)은 실제로 보기 어려워 미리보기로 확인한다. 지금의 카드 하나짜리 미리보기는 이것으로 바꾼다. (R-45)
- AppNavHost는 설정 화면에 뒤로 가기 콜백을 넘긴다: `SettingsScreen(onBack = …)`. 콜백이 불리면 설정 화면을 걷어 들어오기 전의 화면으로 돌아간다. 화면 이동의 맨 위가 설정 화면(경로 `settings`)일 때만 걷는다. 버튼을 빠르게 두 번 눌러도 시장 분위기 화면까지 걷히지 않게 하기 위함이다. 기기의 뒤로 가기는 화면 이동(Navigation)이 원래 하는 대로 둔다. 버튼과 기기의 뒤로 가기가 같은 길로 돌아간다. (R-44, P-11)
- 뒤로 가기로 벗어나면 설정 화면의 ViewModel이 사라져 저장을 누르지 않은 글자와 키 보기 여부가 함께 없어진다. 확인 중이거나 저장하지 못한 키는 KeyCheckManager에 남아 다시 들어오면 보인다. 지금 코드가 이미 그렇게 동작하므로 이것을 위해 더할 코드는 없다. (R-36, R-37, P-11)

## 3. 수동 확인

- R-02: Given 시장 분위기 화면 / When 메뉴의 "설정"을 눌러 설정 화면을 연다 / Then 위에서 아래로 위쪽 줄(뒤로 가기 버튼, "설정"), 안내 "데이터를 받으려면 출처마다 키가 필요합니다. 키는 이 기기에만 저장됩니다.", 출처 카드 순서로 보인다
- R-03 (카드 표시): Given 설정 화면 / When 화면을 본다 / Then Twelve Data 카드가 위에, FRED 카드가 그 아래에 보인다
- R-04: Given Twelve Data에는 키가 저장되어 있고 FRED에는 키가 없음 / When 설정 화면을 연다 / Then 두 카드 모두 출처 이름, 그 아래 한 줄("주식과 ETF 가격", "금리와 채권 지표"), 출처 이름 오른쪽의 딱지가 보인다
- R-05 (딱지의 글과 색): Given Twelve Data에 맞는 키가 저장됨, FRED에 키 없음 / When 설정 화면을 열고, FRED에 틀린 키 `wrongkey1234`를 넣어 저장을 누른다 / Then Twelve Data의 딱지는 파란 "저장됨"이고, FRED의 딱지는 저장을 누르기 전에는 회색 "키 없음", 거절된 뒤에는 빨간 "틀림"이다. 시장 분위기 화면의 키 안내 카드에 보이는 딱지와 글과 색이 같다
- R-06 (요소 표시): Given 키가 없는 출처 / When 설정 화면을 연다 / Then 그 카드에 이름표 "API 키", "키를 붙여 넣으세요"가 보이는 빈 입력 칸, "키 발급받기"와 그 아래 "무료, 카드 등록 없음", "저장" 버튼이 보인다
- R-07 (요소 표시): Given 키가 저장된 출처 / When 설정 화면을 연다 / Then 그 카드에 입력 칸, 발급 안내, 저장 버튼이 없고, 점 12개와 키의 끝 네 글자로 가려진 키, 그 오른쪽의 키 보기 버튼, "키 지우기" 버튼이 보인다
- R-08 (표시): Given 키가 없는 출처 / When 틀린 키 `wrongkey1234`를 넣고 저장을 누른다 / Then 입력 칸에 `wrongkey1234`가 남아 있고 칸의 테두리가 빨갛다. 발급 안내와 저장 버튼은 그대로 있다
- R-10: Given 키가 없는 출처의 빈 입력 칸 / When 글자를 치고, 지운 뒤 복사해 둔 키를 붙여 넣는다 / Then 친 글자와 붙여 넣은 키가 칸에 들어간다. 키보드가 올라와 있어도 입력 칸과 저장 버튼을 볼 수 있다
- R-13 (긴 키의 표시): Given FRED에 32글자 키가 저장됨 / When 키 보기 버튼을 누른다 / Then 가려진 키 자리에 키 전체가 잘리지 않고 보인다(한 줄에 다 들어가지 않으면 다음 줄로 넘어간다). 버튼은 키 가리기 모양(눈에 빗금)으로 바뀌고, 다시 누르면 키가 가려진다
- R-14: Given 키가 저장된 출처 / When "키 지우기"를 누른다 / Then "이 키를 지울까요?"라고 묻는 창이 뜬다
- R-15 (브라우저 열기): Given 키가 없는 두 출처 / When 카드마다 "키 발급받기"를 누른다 / Then 브라우저에서 Twelve Data는 `https://twelvedata.com/register`, FRED는 `https://fredaccount.stlouisfed.org/apikeys`가 열린다
- R-26 (비활성 모양): Given 키가 없는 출처의 빈 입력 칸 / When 저장 버튼을 누르고, 그 뒤 글자 하나를 넣는다 / Then 칸이 비어 있을 때는 저장 버튼이 흐리게 보이고 눌러도 반응하지 않는다. 글자를 넣으면 파란 버튼이 된다
- R-28 (표시): Given 저장되어 있던 키가 틀림이 된 상태(실제로 만들기 어려우면 Android Studio의 미리보기로 본다) / When 설정 화면을 연다 / Then 딱지가 "틀림"이고, 키는 가려진 채이며, 그 아래에 "키가 거절됐습니다. 지우고 다시 넣어 주세요."가 보인다. "키 지우기" 버튼이 있다
- R-32 (진행 표시와 "확인 중"): Given 키가 없는 출처에 키를 넣음 / When 저장을 누른다 / Then 확인이 끝날 때까지 저장 버튼 자리에 돌아가는 진행 표시와 "확인 중"이 보이고, 그 카드의 입력 칸은 고칠 수 없다. 다른 카드는 그대로 쓸 수 있다(확인이 금방 끝나 보기 어려우면 모양은 Android Studio의 미리보기로 본다)
- R-33 (앱을 다시 켜면 가림): Given 키 보기를 눌러 키 전체가 보이는 상태 / When 앱을 껐다 다시 켜고 설정 화면을 연다 / Then 키가 가려진 상태로 보인다
- R-35: Given "이 키를 지울까요?" 창이 떠 있음 / When 취소를 누른다 / Then 창이 닫히고 키와 딱지가 그대로다
- R-37 (화면을 벗어났다 돌아오기): Given 키를 넣고 저장을 누른 직후(확인 중) / When 뒤로 가기로 시장 분위기 화면에 갔다가 다시 설정 화면에 들어온다 / Then 그때의 결과가 보인다. 아직 확인 중이면 확인 중 표시, 저장됐으면 저장됨의 모양, 저장하지 못했으면 넣었던 키와 그 안내다
